작성일 2026-11-16. 코드 구현을 의뢰하기 위한 준비 문서다. 기준 제안은 [v002 제안서](NEXT_TRAINING_PROPOSAL.md), 구현 계약은 [코드 생성 명세](NEXT_TRAINING_CODEGEN_SPEC.md), 수량·설정·패널 ID는 [기계 판독용 계획](../training/proposals/v003/preparation-plan.json), 확인한 원본은 [근거 스냅샷](../training/proposals/v003/preparation-evidence.json)에 있다. v003은 문서 패키지 버전이며 향후 코퍼스 버전은 `corpus-1100-v002`로 예정한다.

## 분석을 반영한 보완

기존 Kaggle 생성 110개에서 두 CPU 속성은 모두 정답과 같았다. B1의 직접 근거는 고정 출력의 비용과 배포 시 속성 오생성이다. 정답에서 두 속성과 앞 공백을 빼면 함수당 143토큰, 총 정답 토큰의 약 10.31% 감소로 재계산됐다. 이는 저장 토크나이저의 ASCII BPE 규칙을 재현해 얻은 값이며 구현 단계에서 공식 tokenizers로 전량 교차 검증한다. 신규 모델의 실제 토큰 수·지연시간 감소는 후속 실험에서 측정한다.

현재 로컬에 남아 있는 입력은 x에 1, y에 2를 더한 뒤 곱하는 함수다. 생성 IR이 x 갱신을 생략해 256입력 전부에서 실패했다. 이 사례를 알려진 회귀 사례로 등록한다. 기존 생성기는 acc 대입만 허용하므로 B2의 x/y 재대입은 명시적인 문법 확장이다. 지원 범위에 맞춰 AST 검사·렌더러·해석기·입력 생성과 테스트를 함께 구현해야 한다.

combined 오답 14개는 모두 명령·피연산자 구조 차이가 있는 그룹이다. 상수 보강과 함께 갱신 순서·값 사용 위치·출력 길이별 진단이 필요하다. 기존 coarse shape 989종 중 944종이 singleton이므로 그 해시의 미관측 여부만으로 template OOD를 정의하지 않는다.

| 분류 | 신규 train | 최소 기본 단위 함수 | 최소 x/y 재대입 함수 | 신규 dev IID/OOD | 신규 final IID/OOD |

기본 단위 함수와 재대입 함수의 최소 수량은 서로 다른 행으로 충족한다. 나머지 1,360행에는 다양한 상수, 식 깊이, 의존 사슬, 기존 구조 및 새 구조를 배분한다. 기본 단위 함수는 연산별 최소 한 예제를 포함하고, 나머지는 새 구조·반환 위치·변수 사용 조합으로 채운다. 구조 중복 규칙 때문에 최소 수량을 채울 수 없으면 생성 전 catalog 점검에서 계획을 조정한다. 숫자만 바꾼 행으로 수량을 채우지 않는다.

상수 0·1·31·32, 2의 거듭제곱 전후, uint32 최댓값, 큰 난수, 마스크, 시프트 0·31, 오버플로·상수식 접기는 다중 태그로 관리한다. 태그별 train 수와 길이 분포를 보고한다. 신규 dev/final의 재대입 비중과 길이는 분류·IID/OOD 안에서 가능한 한 맞추고 실제 차이를 공개한다.

## 개발 패널과 선택

기존 validation 25개는 기존 probe 20개를 포함하고 분류별 1개씩 추가했다. 추가 ID는 기존 probe 이외 validation ID를 `SHA256("v003-panel:" + id)` 오름차순으로 선택했다. 정확한 ID는 계획 JSON에 고정했다. 신규 25개는 분류별 IID 3개와 OOD 2개이며, 생성·검증 후 같은 해시 정렬로 선택한다. 최종 시험을 보고 패널을 바꾸지 않는다.

초기 B0/B1은 기존 25개에서 평가한다. 신규 데이터 준비 후 B0/B1의 새 25개를 채우고 B2의 전체 50개를 평가한다. 기본 합계는 150회 추론이다. 첫 속도 측정 5개는 이 패널의 분류별 최장 정답 1개로 구성하고 동일 run의 완료 예측을 재사용한다. 정답 길이는 로컬 스케줄러가 사용하며 추론 payload에 실리지 않는다.

B2의 주 선택 지표는 50개 패널의 공통 프로필 시스템 함수 성공이다. v1 대안이면 같은 기준으로 B0와 비교한다. 순증 5개와 combined 순증 2개를 유망 신호로 사용하고 다른 분류에서 순감소 2개 이상이면 회귀 원인을 기록한다. 신호를 충족하지 못하면 최종 대규모 시험 전에 반례·분포를 조사한다. 후보가 여러 개면 성공 수, combined 성공 수, 생성 토큰 중앙값 순으로 동률을 해소한다. 추가 실험을 도입하면 실행 전에 계획·비용·선택 규칙을 개정한다.

## 비용과 실행 준비 상태

기존 평균 212.1초를 적용하면 T4 두 대에서 150회 추론의 이상적 시간은 약 4.42시간이다. 5시간 상한에는 약 35분의 여유만 있다. checkpoint 하나의 50회 평가를 추가하면 약 1.47시간이 더 든다. B1 학습 3시간, B2 학습 7시간, 개발 추론 5시간의 계획 상한을 유지한다. B1 기존 패널 추론도 5시간에 포함한다. 환경 준비·모델 적재가 상한을 초과할 때는 예산을 재산정하고 후속 job을 분리한다.

최종 400회 추론은 T4 두 대 기준 약 11.78시간이며 준비 비용을 포함한 계획 상한은 14시간이다. 이 수치는 두 worker의 벽시계 계획이며 GPU 할당량과 다르다. 단일 GPU로 실행하면 추론 시간은 대략 두 배다. 600초 함수 제한은 점수 정책이고 job 상한은 자원 정책이다. job 중단·재개는 완료 ID를 보존하며 미완료 패널을 완성된 점수로 발표하지 않는다.

현재 완료한 것은 명세·설정 계획·기존 패널 확정·근거 파일 대조다. 아래 항목은 구현 후 완료해야 한다.
