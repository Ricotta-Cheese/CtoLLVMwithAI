# Qwen 비교 학습 실험

직접 학습한 모델과 Qwen2.5-Coder-1.5B의 미세조정 전·후를 기존 검증 세트에서 비교합니다. 모델을 최종 선택하기 전의 첫 탐색 실험이며, 시험 세트는 사용하지 않습니다.

## 고정한 조건

- 데이터: 기존 파일럿 100쌍, 학습 80개·검증 10개·시험 10개.
- 데이터 SHA-256: `eee59320108906a40ea3027b42bcc699428d137f9ba11c74140dc23efddda832`.
- 평가 프롬프트: 기존 C 코드와 타깃을 담은 원문. Qwen에는 chat template을 적용하지 않습니다.
- 대상 Qwen: Instruct가 아닌 `Qwen/Qwen2.5-Coder-1.5B` base 모델.
- 모델 리비전: `df3ce67c0e24480f20468b6ef2894622d69eb73b`.
- 비교 대상: 직접 만든 모델의 175 step 가중치, Qwen 4비트 기준 모델, QLoRA 미세조정 모델.
- 생성: 함수당 greedy 후보 한 개, 문맥 길이 3,072, 신규 토큰 상한 2,560. 직접 만든 모델은 기존 학습 시의 `<|ir|>` 경계 토큰을 유지합니다.
- 출력 원문을 저장하고 자동 수정·코드 블록 제거·타깃 변경 없이 평가합니다.
- 직접 만든 모델의 생성 한도는 함수당 120초이며 모든 검증 함수가 10초 이내에 EOS로 완료됐습니다. Qwen도 두 번째 시도에서는 함수당 120초를 사용했습니다. 긴 함수의 출력 중단을 확인해 세 번째 시도부터 Qwen 한도를 300초로 늘렸습니다. 이전에 EOS로 완료된 동일 리비전의 기준 출력은 보존해 재사용합니다. 한도에 걸린 기준 출력은 늘어난 한도로 다시 생성합니다.
- 직접 만든 모델은 KV cache를 추가한 추론 경로를 사용합니다. 작은 모델과 실제 학습 가중치에서 기존 전체-prefix 연산과 logits·다음 토큰이 일치하는지 확인했습니다. 가중치와 아키텍처는 바꾸지 않았습니다.

정확한 실행 계획은 [`training/qwen-comparison-plan.json`](../../training/qwen-comparison-plan.json)에 보관합니다.

## Qwen 학습 조건

4비트 NF4 및 double quantization으로 기본 가중치를 불러오고, rank 8·alpha 16·dropout 0.05의 LoRA를 선형 계층에 적용합니다. 업데이트 대상 파라미터는 9,232,384개입니다.

배치 1·누적 4·학습률 0.0001·warmup 5 step으로 60 step을 진행합니다. 학습 80개 기준 약 3 epoch에 해당합니다. 20·40·60 step에서 같은 검증 자료의 loss를 측정하고 가장 낮은 체크포인트를 선택합니다. 정답 IR과 종료 토큰에만 손실을 적용하며 프롬프트와 패딩은 제외합니다. Qwen 토크나이저에서 pad와 EOS가 같은 경우에도 실제 EOS의 학습 신호를 유지합니다.

실행 환경은 Kaggle T4 단일 GPU로 고정합니다. 사전 설치된 PyTorch를 공유하는 별도 Python 환경에 Transformers 4.57.6, PEFT 0.18.1, Accelerate 1.12.0, bitsandbytes 0.49.1, tokenizers 0.22.2를 설치합니다.

직접 만든 모델은 약 2,725만 파라미터, Qwen은 약 15억 파라미터이며 토크나이저·사전학습·학습량도 다릅니다. 이번 비교는 실용적인 후보 선택을 위한 비교이며, 사전학습 효과 하나만 분리하는 실험이 아닙니다. 토크나이저가 다르므로 모델 간 loss를 직접 비교하지 않습니다.

## 컴파일 및 동작 평가

생성된 macOS ARM 타깃 IR을 로컬의 잠긴 Apple Clang 21 환경에서 검사합니다. 데이터 생성 시의 환경 잠금에는 Python 3.14.8이 포함되어 있어 평가 명령에는 `python3.14`를 사용합니다.

검증 함수마다 저장된 경계값·고정 난수 입력, 기본 256개를 사용합니다. 모든 모델이 동일한 함수·입력·기대값으로 평가됩니다.

1. 출력이 EOS로 종료됐는지 기록합니다.
2. LLVM 파서와 verifier를 실행합니다.
3. 대상 타깃·함수 ABI·현재 지원하는 정수/지역 스택 메모리 범위에 맞는지 확인합니다.
4. 호출용 C harness와 연결해 실행 파일을 만듭니다.
5. 입력 전체의 출력이 기준값과 일치하는지 확인합니다. 오류·시간 초과·출력 개수 불일치도 실패에 포함합니다.

LLVM에서 타깃 지시문 생략은 합법적이므로 생략된 경우에는 잠긴 네이티브 타깃을 명시해 검사합니다. 명시된 triple과 datalayout이 다른 경우에는 계약 검사에서 거부합니다. 외부 함수 호출·전역 상태·임의 포인터 연산 등 현재 범위 밖의 코드는 실행하지 않습니다. 구조적으로 유효한 IR이 계약 검사에서 거부된 경우는 별도 집계합니다.

분모는 항상 검증 함수 전체 10개입니다. 실행 성공 함수는 입력 전체를 통과해야 합니다. `execution_passed`는 유한 입력 전체의 결과 일치, `function_success`는 결과 일치와 EOS 종료를 모두 충족한 경우입니다. 출력 완료율·LLVM 검증률·계약 통과율·컴파일 성공률도 분리해 기록합니다.

평가기는 [`training/evaluate_generated_ir.py`](../../training/evaluate_generated_ir.py), 집계기는 [`training/compare_model_reports.py`](../../training/compare_model_reports.py)입니다. 생성 IR과 함수별 검사 결과, 첫 불일치 입력, 오류 메시지, 데이터·코드·도구 해시를 보관합니다. 유한 입력 검사는 모든 입력에 대한 동등성 증명이 아닙니다.

## 실행 이력

- 버전 1: Kaggle 이미지의 `ensurepip` 문제로 환경 준비 중 중단. 모델 학습 없음.
- 버전 2: 기준 모델 로딩 및 학습 전 출력 수집 완료. Trainer가 두 GPU로 자동 복제하면서 양자화 연산 오류 발생. 학습 전 평가에서 중단.
- 버전 3: `CUDA_VISIBLE_DEVICES=0`을 모델 import 전에 설정하고 Trainer의 GPU 수가 1인지 확인. 완료된 기준 출력은 재사용하고 미완료 출력은 늘어난 한도로 재생성.

실패 로그는 `training/kaggle-qwen-001/attempts/`, 두 번째 시도 출력은 `training/kaggle-results/qwen-attempt2/`에 보관합니다. 최종 결과는 성공한 실행의 출력과 로컬 평가 결과를 기준으로 기록합니다.

## 첫 비교 결과 — 2026년 11월 13일

Kaggle 버전 3이 `COMPLETE`로 종료됐습니다. 60 step, 약 3 epoch의 QLoRA 학습을 완료했고, 최저 검증 loss 체크포인트는 60 step입니다. 학습 함수 경과 시간은 약 658.5초, 최대 GPU 할당 메모리는 약 7.34GiB였습니다. 작업 후 GPU 할당량은 28.87시간 남았습니다. 실패 시도와 기준·학습 후 생성 시간까지 포함한 계정 사용량이며, 순수 학습 시간과 구분합니다.

Qwen 자체의 검증 loss는 학습 전 0.67611에서 20 step 0.08332, 40 step 0.02035, 60 step 0.01820으로 감소했습니다. 이 수치를 직접 만든 모델의 loss와 비교하지 않습니다.

### 함수별 성공과 실패

성공한 `arithmetic-017`, `bitwise-016`은 각각 저장된 256개 입력 전체에서 기준값과 일치했습니다.

| 함수 | 결과 | 관찰된 원인 또는 첫 반례 |
|---|---|---|
| arithmetic-017 | 성공 | 256/256 입력 일치 |
| arithmetic-007 | LLVM 검증 실패 | 숫자 SSA 식별자 순서 오류 |
| bitwise-016 | 성공 | 256/256 입력 일치 |
| bitwise-015 | LLVM 검증 실패·시간 한도 | 정수 값을 포인터로 사용 |
| branch-018 | LLVM 검증 실패 | 지역 SSA 이름 중복 정의 |
| branch-017 | 실행값 불일치 | x=0, y=0: 기대 0, 실제 7168 |
| combined-010 | LLVM 검증 실패 | 정수 값을 포인터로 사용 |
| combined-019 | LLVM 검증 실패·시간 한도 | 정의되지 않은 메타데이터 참조 |
| loop-018 | 실행값 불일치 | x=0, y=1: 기대 1, 실제 4294967294 |
| loop-005 | LLVM 검증 실패 | 포인터 값을 정수 연산에 사용 |

`bitwise-015`와 `combined-019`는 300초 생성 한도에 도달했으며 EOS가 없었습니다. 잘린 출력을 자동 완성하거나 수정하지 않았습니다. 이 중 전자는 이미 생성된 부분에 타입 오류가 있었고, 후자는 메타데이터 정의가 완성되지 않았습니다.

직접 만든 모델은 잘못된 모듈 헤더와 함수 선언 때문에 10개 모두 LLVM 검증에 실패했습니다. 학습 전 Qwen은 IR 대신 C 코드를 생성하는 등 원문 프롬프트에서 요구한 출력 형식을 따르지 못했습니다. QLoRA 학습으로 출력 형식과 일부 동작 정확도가 개선됐지만, 타입·SSA 일관성과 분기·반복문 변환에는 오류가 남아 있습니다.

### 다음 비교에서 확인할 항목

1. 현재 오류가 많은 분기·반복문, 포인터/정수 구분, SSA 이름 일관성을 다루는 학습 자료를 보강합니다.
2. 고정 모듈 헤더와 메타데이터를 프로그램이 조립하고 모델이 함수 본문에 집중하는 실험을 별도 데이터셋 버전으로 비교합니다.
3. 데이터 확장 후 같은 구조 분리 기준·실행 입력·단계별 지표로 두 모델을 다시 비교합니다.
4. 입력 전체의 실행 일치율과 추론 시간·메모리를 함께 보고 최종 후보를 정합니다. 시험 세트는 그 전까지 학습과 튜닝에 사용하지 않습니다.

## 모델 개발 방향 변경

2026년 11월 13일 사용자 결정에 따라 직접 만든 모델의 추가 학습을 중단하고 Qwen 계열을 주력으로 사용합니다. 기존 직접 학습 모델의 가중치·검증 기록은 실험 이력으로 보존합니다. Qwen2.5-Coder-1.5B의 미세조정 결과를 기준선으로 유지하고, 다음 크기 후보는 Qwen2.5-Coder-3B입니다. 3B 학습은 아직 시작하지 않았으며 먼저 단일 T4에서 메모리와 처리 속도를 시험해야 합니다.
