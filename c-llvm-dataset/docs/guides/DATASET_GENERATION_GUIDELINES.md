# 데이터셋 생성 전 확인 지침

이 문서는 C–LLVM IR 데이터셋을 새로 생성하거나 규모를 늘리기 전에 확인할 작업 기준입니다. 현재 구현인 `c-llvm-dataset` v0.1.0에 맞추어 작성했습니다. 명령은 프로젝트 루트에서 실행합니다.

기존 100쌍은 파이프라인 점검용 파일럿입니다. 새 데이터셋을 만들 때에는 입력 언어의 범위, 실행 환경, 검증 기준, 재현성 근거를 함께 기록해야 합니다. 구현의 세부 실행 방법은 [프로젝트 README](../../README.md)를 참고하세요.

## 1. 생성 목적과 지원 범위 확인

- [ ] 생성 목적을 정합니다. 기존 파일럿 재현, 수량 확대, 문법 확장, 다른 타깃용 생성 중 어떤 작업인지 기록합니다.
- [ ] 데이터셋 이름과 새로운 출력 경로를 정합니다. 기존 `artifacts/`를 삭제하거나 덮어쓰는 방식으로 갱신하지 않습니다.
- [ ] C 입력과 LLVM IR 출력의 범위를 정합니다. 현재 입력은 함수 하나이며, 출력은 설명이나 Markdown 코드 블록이 없는 전체 LLVM IR 모듈입니다.
- [ ] 지원 범위를 바꾸면 생성기·Python 해석기·C 출력기·검증기를 함께 수정하고, 수작업 정답 테스트를 보강합니다. 설정 수치만 바꿔 미지원 문법을 활성화하지 않습니다.

현재 지원 범위는 다음과 같습니다.

| 항목 | 기준 |
|---|---|
| 언어 | C11 |
| 함수 | `unsigned int compute(unsigned int x, unsigned int y)` |
| 정수 | 정확히 32비트인 `unsigned int`; 연산 결과는 2³²로 나눈 나머지로 처리 |
| 문법 | 덧셈·뺄셈·곱셈, 비트 연산, 안전한 상수 시프트, 분기, 제한된 반복 |
| 초기화 | 모든 지역 변수를 읽기 전에 초기화 |
| 시프트 | 횟수가 0~31인 상수 |
| 반복 | `(x & 15u) + (y & 1u)`회, 최대 16회; 중첩 반복 없음 |
| 제외 | 포인터, 배열, 구조체, 실수, 재귀, 외부 함수 호출, 나눗셈 |
| 정답 IR | Clang `-O0` 출력; 타깃 정보와 의미에 필요한 속성·메타데이터 유지 |

## 2. 도구와 실행 환경 확인

- [ ] Python 3.11 이상과 Clang이 설치되어 있는지 확인합니다.
- [ ] 생성할 IR의 타깃과 실행 검증 환경이 호환되는지 확인합니다.
- [ ] `doctor`가 통과하는지 확인합니다. 올바른 코드의 실행뿐 아니라 잘못된 SSA 지배 관계를 거부하는 검사와 UBSan 실행도 포함합니다.
- [ ] 사용할 환경 잠금 파일을 정하고, 버전 불일치를 잠금 파일 덮어쓰기로 해결하지 않습니다.
- [ ] 생성기·해석기·컴파일 경로·검증 규칙을 바꿨다면 생성 전에 테스트를 실행합니다.

```bash
python3 run_pipeline.py doctor
python3 -m unittest discover -s tests -v
```

현재 기본 잠금은 macOS ARM64, Apple Clang 21, Python 3.14.8, 타깃 `arm64-apple-macosx27.2.0`입니다. 정확한 기준은 [`toolchain.lock.json`](../../toolchain.lock.json)에 있습니다.

`doctor`의 성공은 도구가 정상 동작한다는 뜻입니다. **기존 잠금과 현재 환경의 일치 여부는 `generate`가 별도로 검사합니다.** 현재 잠금에는 Clang 실행 파일 해시, 버전, 타깃, Python 버전, OS·아키텍처, 컴파일 옵션, macOS SDK 버전과 설정 해시가 포함됩니다.

다른 환경에서는 별도 잠금을 생성합니다. 다음 Linux 예시는 Linux 환경에서 실행할 절차이며, 현재 프로젝트에서 Linux 실행 검증을 완료했다는 뜻은 아닙니다.

```bash
python3 run_pipeline.py --clang /path/to/clang doctor --write-lock --lock toolchain-linux.lock.json
```

기존 macOS IR을 Linux에서 네이티브 실행할 수 있다고 가정하지 않습니다. Colab에서는 macOS IR도 텍스트 학습 자료로 읽을 수 있지만, 네이티브 실행 평가는 타깃에 맞는 환경이 필요합니다. Linux용 새 산출물은 macOS 산출물과 다른 데이터셋 프로필로 관리합니다.

## 3. 생성 설정과 다양성 확인

- [ ] [`config.json`](../../config.json)의 시드, 분류별 개수, 경계값, 난수 입력 수, 탐색 한도, 실행 시간 제한을 확인합니다.
- [ ] 기존 데이터셋 재현이 목적이면 설정과 파이프라인 소스 코드를 변경하지 않습니다.
- [ ] 새 실험의 설정은 별도 파일로 보관합니다. 설정 변경과 함께 생성 목적·문법 범위·도구 환경을 추적할 수 있게 합니다.
- [ ] 상수와 변수명만 바꾼 변형으로 수량을 채우지 않습니다. 현재 생성기는 보수적인 구조 해시 중복도 거부합니다.
- [ ] 단순히 생성 시드를 바꿨다는 이유로 다른 학습·시험 데이터라고 판단하지 않습니다. 시드가 달라도 구조가 겹칠 수 있습니다.

현재 기본 설정은 다음과 같습니다.

| 항목 | 값 |
|---|---:|
| 생성 시드 | 20261113 |
| 분류별 수량 | 산술·비트·분기·반복·복합 각 20개 |
| 총 수량 | 100쌍 |
| 샘플별 경계값 입력 | 8개 값의 전체 조합, 64쌍 |
| 샘플별 난수 입력 | 192쌍 |
| 추가 제어 흐름 입력 탐색 한도 | 4,096회 |
| 분류별 후보 생성 한도 | 200개 |
| 개별 도구 실행 시간 제한 | 20초 |

분기 양쪽 결과와 반복 횟수 0·1·16을 확인할 입력이 부족하면 증인 입력을 추가합니다. 따라서 샘플당 입력 수는 기본 256개보다 많아질 수 있습니다. 제어 흐름 확인은 AST 해석기 추적 기준이며, 네이티브 바이너리 분기 계측과 구분합니다.

## 4. 샘플 채택과 실패 처리 기준 확인

다음 검사를 모두 통과한 쌍만 채택합니다.

- [ ] AST가 지원 문법·초기화·상수 범위·반복 제한을 만족합니다.
- [ ] C 컴파일에 경고나 오류가 없습니다.
- [ ] 저장할 IR이 Clang의 LLVM 파서와 내장 verifier를 통과합니다. 별도 `opt`나 `llvm-as` 설치를 전제로 하지 않습니다.
- [ ] 모든 검증 입력에서 Python 기준값, C `-O0` 실행값, 저장된 IR의 실행값, C UBSan 실행값이 일치합니다.
- [ ] sanitizer 진단, 비정상 종료, 시간 초과가 없습니다.
- [ ] 입력 출처와 기대값, AST 추적, 소스·IR 해시, 후보 번호, 검증 결과를 보관합니다.

IR 실행 파일은 `-O2`로 빌드하지만, 정답 IR의 `optnone` 속성 때문에 함수 최적화가 제한될 수 있습니다. 이 경로는 저장된 IR을 다시 읽고 실행하는지 확인하는 검사이며 최적화 품질 평가가 아닙니다.

실패 종류별 처리는 다음과 같습니다.

| 상황 | 처리 |
|---|---|
| 구조 중복, 관측 출력의 상수화, AST 제어 흐름 커버리지 부족 | 후보를 거절하고 사유·AST를 기록; 한도 내에서 다음 후보 생성 |
| 도구 오류, LLVM 검증 오류, 실행값 불일치, sanitizer 오류, 시간 초과 | 전체 생성 중단; 원인을 조사한 뒤 새 실행으로 재검증 |
| 분류별 후보 한도 소진 | 목표 수량 미달로 실패 처리 |
| 환경 잠금 불일치 | 환경을 복원하거나 별도 환경 프로필 사용 |

부분 결과가 들어 있는 `artifacts-v002.work-*` 같은 작업 디렉토리를 학습 데이터로 사용하지 않습니다. 성공한 실행만 최종 출력 경로로 이동합니다. 실패한 검사나 sanitizer 옵션을 끄고 같은 데이터셋을 통과 처리하지 않습니다.

## 5. 생성 후 확인할 절차를 미리 준비

아래 출력 경로 두 개는 모두 존재하지 않아야 합니다. 이미 존재한다면 새 이름을 선택합니다. 예시는 기존 기본 설정과 환경 잠금을 사용하는 신규 실행입니다.

```bash
# 새 데이터셋 생성
python3 run_pipeline.py generate --config config.json --lock toolchain.lock.json --output artifacts-v002

# 파일 해시·수량·AST·학습 행·기대값 일치 확인
python3 run_pipeline.py validate artifacts-v002

# 보관된 C와 IR을 다시 컴파일하고 실행 비교
python3 run_pipeline.py validate artifacts-v002 --execute

# 다른 절대 경로에서 독립 재생성 후 파일 전체 비교
python3 run_pipeline.py generate --config config.json --lock toolchain.lock.json --output /tmp/c-llvm-v002-reproduction
python3 run_pipeline.py compare artifacts-v002 /tmp/c-llvm-v002-reproduction
```

- [ ] 모든 명령의 종료 코드가 0인지 확인합니다. 마지막 명령은 `status: identical`을 반환해야 합니다.
- [ ] `validation.json`의 총 수량·분류별 수량·입력 수·검증 상태를 확인합니다.
- [ ] `manifest.json`에 설정·도구 잠금·파이프라인 소스 해시와 파일별 SHA-256이 있는지 확인합니다.
- [ ] `rejections.json`의 거절 사유와 분포를 검토합니다. 특정 분류의 지속적인 실패를 단순한 수량 증가로 가리지 않습니다.
- [ ] `compare`의 데이터·manifest 해시와 비교 범위를 해당 실험의 재현성 기록으로 별도 보관합니다.

`validate`만 실행하면 저장된 증거의 무결성과 내부 일치 여부를 검사합니다. 컴파일 및 실행을 다시 수행하려면 `--execute`가 필요합니다. 두 독립 생성 결과의 바이트 일치는 `compare`로 확인합니다.

현재 루트의 [`reproducibility.json`](../../reproducibility.json)은 기존 100쌍의 재현성 기록입니다. 새 실험의 근거로 재사용하지 않습니다. `compare`는 결과를 표준 출력으로 반환하며 이 기록 파일을 자동으로 갱신하지 않습니다.

재현성 확인 범위는 **동일한 설정·소스 코드·잠긴 도구 환경**입니다. 현재 잠금은 전체 OS를 보관하는 컨테이너 이미지 잠금이 아니며, 다른 OS·아키텍처·LLVM 버전에서 동일 IR 바이트를 보장하지 않습니다.

## 6. 학습 데이터로 넘기기 전 확인

- [ ] 파일럿 100개는 생성·검증 파이프라인 점검용이라는 점을 기록합니다. 이 수량만으로 일반적인 C 컴파일 능력을 주장하지 않습니다.
- [ ] 본학습 데이터는 학습·검증·시험을 구조 식별자와 생성 계열 기준으로 분리합니다. 기존 파일럿에는 아직 이 분할이 없습니다.
- [ ] 별도 생성 실행끼리도 구조 중복과 C–IR 쌍 중복을 확인합니다. 현재 자동 중복 검사는 한 번의 생성 실행 내부에 적용됩니다.
- [ ] 시험 세트를 생성기 보완·모델 선택·학습 설정 조정에 반복 사용하지 않습니다.
- [ ] `prompt`와 `completion`만 학습 입력·정답으로 연결하고, 이미 프롬프트에 들어 있는 `c_source`를 중복 연결하지 않습니다.
- [ ] 사용할 토크나이저로 입력과 정답의 합산 길이를 확인합니다. 길이 초과 시 샘플을 별도 처리하며 IR 끝을 잘라 정답으로 사용하지 않습니다.
- [ ] 검증 입력·기대값·검증 로그를 모델의 입력 프롬프트에 섞지 않습니다.
- [ ] 타깃·컴파일 옵션·데이터 출처를 보관하고, 서로 다른 프로필을 혼합하려면 모델 입력에서 구분할 규칙을 먼저 정합니다.

현재 파이프라인이 자동으로 수행하는 것은 생성, 실행 내부 중복 검사, 구조·실행 검증, 증거 저장입니다. **실행 간 중복 검사, 학습·검증·시험 분할, 모델 토크나이저 길이 검사는 후속 학습 준비 작업**입니다.

검증 결과는 준비한 유한 입력에서의 일치 근거입니다. 모든 입력에서의 의미 동등성이나 정의되지 않은 동작의 완전한 부재를 증명한 결과로 표현하지 않습니다.
